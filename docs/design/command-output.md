# 命令输出的所有权与失败语义

## 决策

所有业务命令自身的普通消息由命令级呈现模块统一管理，stdout 只承载主要内容，stderr 承载诊断。文件操作是否完成与输出是否完整分别判断；诊断故障不是业务取消请求。各命令的输出通道在 `docs/commands/` 对应页面说明，本文记录实现边界与设计依据。

选择“诊断失败后继续业务”，而不是“任何输出故障立即停发任务”，是因为 decrypt 的主要交付是目标文件：日志接收方关闭不代表用户撤销了解密请求。相反，view/diff 的正文交付本身就是命令目标，正文无法写入时停止后续内容处理。

## 模块职责

- CLI 取得 Cobra 的输入输出通道和显示设置。可复用 module 不修改全局信号处理。
- app 编排选择、业务执行和呈现，并在命令收尾时合并业务错误与输出错误。
- `internal/presentation` 的命令级实例负责正文写入、诊断文案、相对路径、verbose 筛选、完整行串行输出，以及每个通道的首次故障记录。正文不进入诊断事件或日志缓存。
- task 保留并发、结果汇总及业务判定，通过串行完成通知交回结果，不依赖 presentation。诊断故障不能阻止剩余文件调度。
- seal、diff 的文件操作和项目元数据写入不打印；diff 计算内容差异，presentation 决定颜色与报告。
- task.Summary 与 diff.Summary 保留各自结果分类、统计和 strict 判定，不强行合并业务语义。报告文案不属于 Summary 的接口。
- prompt 是独立交互模块，负责缓冲输入与问题交付；它与命令共享诊断故障状态，但问题写入失败必须终止交互。

输出规则集中在 presentation，文件处理模块不承担呈现职责。通过 `io.Writer` 接入终端、内存缓冲区和测试用故障 writer，不增加日志框架或通用事件总线。

## 输出失败

正文写入直接返回输出错误；普通诊断调用只记录故障，命令结束时统一取得错误。两者不能共用一个让所有业务调用遇输出错误就返回的策略。业务错误与输出错误同时存在时保留两者身份；失效 stderr 不回退到 stdout。

每个通道只记录首次写入故障，之后不再向该通道写入。输出故障使 CLI 最终返回 `1`，但不增加文件失败计数，也不回滚已成功写入的文件。目标文件写入失败仍按对应命令的业务规则处理，不归为诊断故障。

交互问题写入失败时，init 不读取答案、不采用默认答案，也不开始后续操作。显式 `init --force` 已表达覆盖意图，其操作前警告属于普通诊断；警告输出失败不取消已授权的初始化，最终仍返回输出错误。

管道断开遵循操作系统和 Go 的默认行为；正文输出仍然只承载主要内容，诊断输出和汇总走 stderr。EPIPE 不作为成功特例，因为无法区分接收方是主动读够还是异常退出。

## 验证与范围

测试通过呈现和命令接口检查正文不污染、默认与 verbose 信息量、重复报告、短写、并行完整行，以及 init 问题失败不执行后续操作。`mise run check` 执行常规检查，`mise run test:race` 检查受影响模块的数据竞争。

本次不改变文件选择、授权或编辑写回规则，不新增命令、通用日志模式、动态 TTY 进度或编辑器终端接管机制。
