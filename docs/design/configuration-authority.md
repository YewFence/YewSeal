# 配置作为唯一声明来源

## 状态

本文档记录 YewSeal 把 `.yewseal.toml` 确立为文件映射与加密授权唯一声明来源的系列决策。相关变更已实现并通过 `mise run check`。

## 设计原则

1. 文件映射、分组和加密授权只来自项目配置；CLI 参数只负责选择、筛选和本次输出位置。
2. 格式只来自配置声明或已登记路径的推断，不提供运行时格式覆盖。
3. 公开授权（recipients）与私有身份（key）是两个独立领域；私钥路径与同步不属于项目配置。
4. 业务命令没有配置即失败，不靠空配置或隐式默认兜底。
5. 宽松处理是批量操作在多人身份环境下的默认，完整性要求由显式严格模式承担。

## 决策

### 移除无配置临时模式

**决策**：业务命令不再接受通过 flags 临时声明文件和 recipients 的用法；`path` 参数只用于选择已登记文件。

**理由**：同时维护 flags 与配置两套声明，会让同一条命令拥有两套文件与授权来源——已登记目标是否被覆盖、未登记目标是否临时构造映射、recipient 替换还是合并、执行后是否回写配置，都需要额外规则；命令语义也会随目录中是否存在配置、文件是否已登记而漂移。

**边界**：`--output` 只改变本次输出位置，位置参数只选择已登记文件，`--key-file` 只提供解密身份；三者都不声明新授权。临时单文件任务由 SOPS CLI 承担，见[与 SOPS 配合使用](/guide/sops)。

### 移除业务命令的 --format

**决策**：`encrypt`、`decrypt`、`plan`、`view`、`diff` 没有 `--format` 选项，也不读取 `YEWSEAL_FORMAT`、`SOPS_FORMAT`。

**理由**：运行时格式覆盖与配置声明天然冲突：覆盖单文件时会绕过配置的格式治理，批量时又无法适用；跨格式转换还会引入"解密成功但转换失败"的中间状态，混淆命令职责。格式是文件的属性，应当由配置声明。

**边界**：格式由 FilePair 的 `format`、Group 的 `format_rules` 或已登记路径的推断结果确定；`--output` 不改变格式。`init --format` 保留，用于在创建配置时声明格式。

### 私钥路径不属于项目配置

**决策**：移除 `[key].file_path`，配置不再包含任何私钥位置。

**理由**：私钥路径是个人或机器的状态，进入共享的项目配置会泄漏本地布局、在多台机器间冲突，也让 CI 无法用环境变量灵活切换身份。

**边界**：解密身份来自 `--key-file`、`YEWSEAL_AGE_IDENTITIES`、`SOPS_*` 环境变量或默认 `.age/keys.txt`；加密授权只来自 registry/defaults，私钥文件不决定加密授权。

### 不提供内置私钥同步

**决策**：不提供 `sync` 命令或 `[sync]` 配置，也不集成任何 secret manager provider。

**理由**：私钥的远端存储、分发和访问控制是部署环境的职责；内置同步会让 YewSeal 承担 provider 认证、权限模型和密钥生命周期，超出"加密配置文件"的边界。

**边界**：外部工具导出私钥的参考脚本见[外部私钥来源](/guide/private-keys)。

### 业务命令必须找到配置

**决策**：版本、帮助、补全和 `init` 不读取配置；其余业务命令在参数校验后统一加载一次配置，找不到配置文件即失败，不回退到空配置。

**理由**：无配置兜底会掩盖"在错误目录执行"或"忘了 init"的错误，让同一命令在不同目录产生不同的隐式行为。

**边界**：配置加载时机详见[配置说明](/guide/configuration)。

### 身份跳过与严格模式

**决策**：`decrypt`、`diff` 默认允许跳过没有匹配身份的文件。decrypt 要求至少成功处理一项，strict 要求所有选中项完成；diff 宽松允许全部跳过，strict 只要求两侧输入均存在的选中映射完成比较，缺输入跳过不影响成功。真正错误始终失败。

**理由**：多开发者、多环境持有不同 Age 身份是常态，批量处理中部分文件不可见是预期结果而非失败；但部署流程需要完整性保证，因此用显式严格模式表达，而不是改变默认语义。

**边界**：跳过不等于成功，也不校验该文件密文完好；`view`、`edit` 不采用宽松策略。结果分类和退出码见[解密结果与严格模式](/guide/decryption-results)。

### 位置参数即选择器，移除 --pattern

**决策**：`encrypt`、`decrypt`、`plan` 移除 `--pattern` 选项；`encrypt`、`decrypt`、`plan`、`diff` 的位置参数扩展为多个选择器——精确路径、目录或 gitignore 方言的 glob 模式，多参数取并集。

**理由**：`--pattern` 与位置参数语义重复，且它对同一映射的明文与密文路径分别求值并互相覆盖，使有序排除规则在映射另一侧失效（如 `--pattern "*.toml" --pattern "!*.enc.toml"` 会意外排空选择集）。单一的选择器轴让"配置决定全集，CLI 只收窄"的模型更易推理；运行时排除能力本就近乎无用，排除规则归配置声明。

**边界**：模式按命令主侧匹配——encrypt 看明文路径、decrypt 看密文路径、plan 和 diff 看两侧；模式只包含不否定，排除只由 Group 的 `patterns` 声明。任一位置参数零命中即报错，无位置参数时仍按当前目录范围选择。

### 统一选择主线，保留命令差异

**决策**：encrypt/decrypt/plan 共享已登记映射的发现、裁决、解析与筛选主线；目录 target 只筛选映射，不重新应用 Group 根目录或发现规则。encrypt 的范围看明文侧，decrypt 看密文侧，文件 target 仍允许匹配任一侧。

**理由**：重新以 target 为根扫描会让 Group 的含义随调用方式变化，也导致目录目标与默认 scope 重复处理授权和显式映射裁决。统一主线应集中这些规则，而不是抹平加密当前授权与读取历史密文的区别。

**边界**：配置加载时机不变。encrypt/plan 严格检查已加载配置所解析出的全部映射的最终授权；decrypt 保留当前 alias 失效时警告后依据密文 metadata 解密的例外。后续 view/diff 迁移也遵循该历史解密例外，edit 暂不调整；task、seal、sopsx 职责不变。

### view 与 diff 的只读选择

**决策**：view 使用单目标历史解密准备，只向 stdout 写明文；diff 按明文侧发现与目录范围选择，但授权处理沿用历史解密例外。任一侧输入不存在时 diff 报告未比较，不作为内容相同或新增、删除补丁。选择成功后始终解析 Identity bundle，不因缺输入跳过身份来源校验。

**理由**：发现哪一侧的文件与如何读取历史授权是不同问题；diff 预览本地已有明文的差异，不承担部署完整性检查。没有比较输入不应该使 diff strict 失败，但应明确报告，不能伪装成已比较。

**边界**：零候选仍是选择错误。两侧存在但无法匹配身份时只有宽松 diff 成功，strict 失败；真正错误始终失败。缺输入不承诺密文已经通过完整性校验。正文与诊断分离，stdout 不插入日志或汇总；诊断写 stderr，输出故障失败。该结果策略不改变 decrypt 的全部跳过失败语义。

### plan 是配置映射检查，不是 dry run

**决策**：plan 无方向地检查映射、格式、当前配置授权及来源；Group 发现采用明文和密文两侧并集，目录范围匹配任一侧。不从 target 后缀推断方向，移除 --output、--parallel 及 SOPS_OUTPUT_FILE 输入，也不展示 metadata 写入计划。

**理由**：原先的 plan 混合了双向目标选择和 encrypt 的严格授权检查，无法准确预演 decrypt。把它定位为配置映射检查，可以同时呈现只有明文或只有密文的映射，不暗示实际操作一定成功。

**边界**：plan 不加载 Identity bundle，不读取密文内容来验证授权或完整性；当前配置授权仍严格检查，历史密文是否可解密不属于它的成功契约。
