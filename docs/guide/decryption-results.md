# 解密结果与严格模式

多开发者、多环境可以持有不同的 Age 身份。`decrypt` 和 `diff` 默认允许跳过没有匹配身份的文件，但不会把密文损坏、读写失败或覆盖冲突当成正常跳过。`view` 和 `edit` 不采用宽松策略，无法解密目标时仍失败；加密的失败判定不变。

## 结果分类

- 成功：完成解密或比较。明文已经一致、比较没有差异也算成功，不要求实际写入文件或产生 diff。
- 跳过：没有匹配的解密身份。该文件没有完成解密和完整性校验，不能据此断言密文完好。
- 失败：已检测到的密文或数据密钥异常、完整性校验失败、缺失文件、读写失败、未获允许的明文覆盖等。无法可靠归类为身份不匹配的错误也按失败处理。

单文件失败后继续处理其他选中文件，最后汇总。参数、配置、身份来源解析以及无法完成扫描等前置错误仍会终止执行；输出通道故障也会使命令失败。

## 严格模式

```bash
# 默认宽松，处理当前身份能访问的文件
yews decrypt
yews diff

# 要求所有选中文件完成处理
yews decrypt --strict
yews diff --strict

# 两个命令共用环境变量，显式 flag 优先
YEWSEAL_STRICT=true yews decrypt
YEWSEAL_STRICT=true yews diff --strict=false
```

未设置 `YEWSEAL_STRICT` 时默认为宽松模式。环境变量使用标准布尔解析，建议写 `true` 或 `false`；实际采用的值无法解析时会报参数错误，包括显式设置为空字符串。显式 `--strict` 或 `--strict=false` 会覆盖环境变量，即使环境变量本身无效。

该变量只在 `decrypt`、`diff` 的业务参数校验阶段读取，不影响版本、帮助、补全、`init`、`encrypt`、`view` 或 `edit`，也没有对应的项目配置字段。严格模式只要求本次选中的范围完整，不扩大选择范围，不意味着遇错停止或整批回滚。

## 退出码

| 情况 | 宽松 decrypt | 严格 decrypt | 宽松 diff | 严格 diff |
| --- | --- | --- | --- | --- |
| 全部成功，无差异 | 0 | 0 | 0 | 0 |
| 全部比较成功，有差异 | 不适用 | 不适用 | 0 | 0 |
| 部分成功，其余因身份不匹配跳过 | 0 | 1 | 0 | 1 |
| 全部跳过 | 1 | 1 | 1 | 1 |
| 存在真正错误 | 1 | 1 | 1 | 1 |

`diff` 是开发预览命令，发现并展示差异本身不算失败；退出码不用于判断文件是否一致。参数、配置或身份来源错误返回 `1`。同一批次既有差异又有真正错误时，仍输出已经得到的 diff，但以 `1` 退出。显式单文件没有匹配身份时也属于全部跳过，不会以成功退出。

## diff 的比较范围

Group 使用配置范围内明文侧与密文侧发现结果的并集，避免只扫描本地明文而漏掉尚未解密的文件；显式文件映射仍按配置处理。如果已有明文路径能够确定映射，优先使用它，而不是仅从密文扩展名反推，例如保留 `config.yml` 与 `config.enc.yaml` 的对应关系。

每个文件先尝试解密，再读取用于比较的本地明文。因此“没有身份，也没有本地明文”可以跳过；能解密但本地明文缺失，或者只有明文而密文缺失，仍是真正错误，不按新增文件差异处理。

diff 内容只写 stdout。stderr 默认列出每个跳过或失败文件及原因，并汇总成功、跳过、失败数量；处理不完整时明确提示 `Comparison incomplete`，无需 `--verbose`。

宽松模式的退出 `0` 表示预览成功，不代表已经比较的文件没有差异，也不保证整个选中范围均已比较。`diff --strict` 只要求完整比较，即使发现差异也返回 `0`。`diff` 的退出码只表示预览是否完成，不用于 CI 判定。

## 文件与元数据

跳过不会创建、删除或更新对应明文，也不会为它创建输出目录。已有旧明文保留，但不算本次处理成功，不能据此继续假定它是最新内容。`--force` 只允许覆盖能够成功解密的文件，不会删除或修改跳过的文件。

`decrypt` 仍在处理文件前按现有项目或目标范围更新 `.gitignore`，包括可能被跳过的明文路径，以避免旧明文误提交。更新失败时不开始写出明文。因此全部跳过并失败时，`.gitignore` 仍可能已经发生变化。`diff` 不写明文或项目元数据。

已经成功处理的文件不会因为后续失败或严格模式不完整而回滚。在 CI/CD 中，应使用 `yews decrypt --strict`，并仅在它成功退出后执行部署。
